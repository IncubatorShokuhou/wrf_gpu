# Experimental scheme GPU qualification

[Summary table](summary.md) and [machine-readable matrix](summary.json) record each measured configuration. Each configuration directory contains matched-input hashes, original CPU-WRF and actual GPU process receipts, E41 scans and D6 field verdicts. Large original CPU/GPU NetCDF outputs are preserved at the paths in `provenance.json`. Retained executable PINs, where present, are listed in `E41_PIN_MAP.json`; disposable compile caches have been removed.

Qualification follows the manager's 2026-10-13 policy: frozen D6 comparison against **original CPU-WRF**, every hourly frame from 0 through 24, with every CPU field inventoried and matching dimensions. Every frame must meet every supplied field threshold; missing fields/frames fail coverage. Fields without a frozen D6 bound are explicitly `REPORT_ONLY`, not numerical passes. The unchanged manifest SHA256 is `9df4fab8514523286f07b127eb8bf57a7545459c4448fef721ac44c0ecc351dc`. `D6.json` retains every failing frame and per-field overall/worst-lead metrics; the full raw per-lead report is hashed in `provenance.json`.

History header attributes are audited on every frame. Some Swiss outputs inherit scheme attributes from the original wrfinput (for example Grell CU_PHYSICS and TKE DIFF_OPT/KM_OPT), while the actual hashed namelist and compiled dispatch select the tested option. The matrix records these metadata differences; they remain an output metadata issue outside the numerical D6 verdict. TITLE and serial-vs-input NTASKS differences are also retained.

Experimental opt-in E41 flags are disclosed and do not change the D6 verdict. `E41.json` preserves the actual full scan verdict and exact kernel/STACK counts; catalog notes repeat applicable flags. Release defaults retain their hard E41 gate. Raw pre-mask F2 negative/nonfinite counts are preserved separately; D6 qualification does not silently justify negative counts or close unrelated release gates.

Swiss cases use the authentic 42x42x44 January 15, 2023 input, dt=18 s, 24 h and hourly output, with the declared option and WRF-required companion settings. Inputs and the actual CPU/GPU namelists are SHA-matched per configuration. NSSL, WSM7 and aerosol-aware Thompson arms explicitly use `GPUWRF_RRTMG_MP_RE=1`. All final arms enable `GPUWRF_CENSUS=1`, retain rich AOT HLO (`GPUWRF_AOT_SLIM_MODULE=0`), and use release fast defaults. An unset `GPUWRF_FAST_DEFAULTS` in the raw environment receipt selects the release's default-on behavior; it is not an explicit override.

RUC and SLUCM use original WPS/real.exe outputs built by the merged `gpuwrf.onboard` pipeline: Madrid, 42x42, 9 km, GFS 2026-10-13 00Z, dt=50 s, matched 24 h forcing. RUC uses the WRF-required six soil levels. The inputs contain 31 actual urban cells. Public GFS downloads total **25,311,585 bytes**, including a third authentic Madrid KM3 case; URLs, hashes, original preprocessing commands and low-resolution geography provenance are in `onboarding.json`, `forcing.json` and the city receipts. No manufactured soil, land-use or boundary values were used. This case does not qualify nine-level RUC inputs or other urban morphology/table options.

Grid-FDDA uses original CPU-WRF hourly analysis fields, correctly paired OLD(t)/NEW(t+1 h) for all 24 intervals. It is a replay-analysis coupling test, not an external-analysis skill claim. Original WRF first refused the helper's versionless TITLE. The corrected file carries the authentic source WRF V4.7.1 version; all 13 variable payloads, dimensions, types and variable attributes remain byte-identical (`fdda1/validation_reuse.json`). Only global descriptive metadata changed. The GPU loader ignores those attributes, so the completed GPU forecast is reused with that certificate; original WRF was rerun successfully on the corrected file. Both original files and the failed first reference are preserved. TDFI uses the original O2 Swiss oracle namelist, with its backward/forward filtering windows preserved and the forecast extended to 24 h. NSSL+Grell-3D has a separate combined-configuration result.

The available pristine WRF build is **serial**. References initially ran on core 29, then on owner-granted cores 0–3/16–18, each with nice 19 and one serial WRF process per core. The executable differs from the original only in two instrumented diagnostic OPEN pathname byte strings, redirected to private files without changing length. `original_CPU_executable.json` and per-case `CPU_executable.json` record hashes/offsets and restoration to the original hash. Original WRF-generated Thompson lookup tables are reused with recorded hashes. Reference timing is not a four-rank benchmark. `CLOCK_AUDIT.json` retains an unexplained CPU UTC/monotonic clock discrepancy; GPU UTC and monotonic durations agree within 0.000038 s.

GPU process receipts assert `jax.devices()[0].platform == 'gpu'`, record clean detached source revisions, actual input hashes and official lock use; private launcher hashes are retained where recorded. GPU arms use the manager lease, driver bridge and bounded daytime windows. Times are **cold shared-CPU/I/O qualification walls**, including initialization/compilation, forecast and output; they are not warm PROD S1 measurements. VRAM is sampled per PID once per second and can miss a short peak. Failed forecast arms have no valid s/fc-h rate; a completed forecast with incomplete field coverage retains its measured rate. The initial RUC ownership failure and its successful fixed reruns remain separate external artifacts; only the selected final run appears in the qualification matrix.

Reproduction uses the retained matched input directories, `gpu_run.json` and `launch.json` where provided, under `scripts/with_gpu_lock.sh --label s1-gpuqual -- ...` with a valid daytime lease and timeout. `tools/gpu_cli.py` is the launcher helper; `tools/score.py <immutable-source> <case-dir>` runs the frozen comparison and full coverage/finite audit on CPU. The remaining helpers preserve CPU reference and input construction commands. CPU work requires `JAX_PLATFORMS=cpu`, assigned cores/nice, and the QUIET guard. Disposable compile caches and snapshots are removed after their last consumer; scientific inputs/outputs, original executable copies and minimal critic PINs remain external.
