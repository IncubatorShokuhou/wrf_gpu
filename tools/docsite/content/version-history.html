Version history and release notes

v0.4.3 — 21 October 2026

A qualification release on the v0.4.2 forecast model: the model source is unchanged apart from the version string, and the compiled programs were compared with those of v0.4.2. It adds a three-nest, 72-hour qualification table against CPU-WRF (Tenerife 9/3/1 km, two kinds of driving data), a status for every item an operational user reported, and a record in the run receipt of whether the computer was suspended during a run. Release notes · Support matrix · Command guide.

v0.4.2 — 19 October 2026

A follow-up release on the v0.4.1 forecast model. The v0.4.1 direct-beam shortwave fix was checked against WRF's code path and stays the default, with an opt-out (GPUWRF_SWDDIR_V040_SPLIT=1) for continuity with v0.4.0; history COSZEN now follows WRF; WDM6 microphysics is about three times faster with identical output; YSU, Shin-Hong, ACM2 and EEPS are validated inside nested domains; new opt-in icloud=0 (radiation without clouds). gpuwrf aot-key no longer writes into compile caches. A heavy-rain finding on one Tenerife forecast is disclosed. The v0.4.1 release notes now also carry a re-measurement of v0.4.1 against v0.4.0 speed. Release notes · Support matrix · Command guide.

v0.4.1 — 18 October 2026

Opt-in additions on top of the v0.4.0 default physics (two default-path fixes are listed in the release notes): experimental ensemble data assimilation (gpuwrf da, LETKF, outer domain only), terrain correction of surface winds (topo_wind=1/2), aerosol in RRTMG shortwave (aer_opt=1/3), WRF radiation cloud fractions (icloud=2/3), Noah-MP surface parameters without recompiling, regional physics studies on the GPU, and stochastic physics checked against CPU-WRF with the same seeds. topo_wind, aer_opt, icloud and the stochastic schemes each passed a 24-hour comparison with the original CPU-WRF in the tested set-ups. Nested runs compile once per grid instead of once per forecast date; the new gpuwrf aot-key shows which compiled programs two cases share. For v0.3.0 to v0.3.4, a compile cache shared across dates could load another date's nested program; on the tested Tenerife grid this changed no output (see the note). Release notes · Support matrix · Command guide.

v0.4.0 — 17 October 2026

The feature release. More than 80 WRF 4.7.1 physics options run on the GPU (microphysics, cumulus, boundary layer, surface layer, land and radiation), together with analysis, spectral, surface and observation nudging, digital filter initialization, two-way nesting, lake, urban and ocean models, wind farms, passive tracers and stochastic physics. New tools set up a forecast for your own region from open GFS data, compute weather and application products, verify against stations, run ensembles, export to NetCDF, Zarr or GRIB2, choose physics for a region and cycle land and snow state.

66 configurations passed 24-hour comparisons with the original CPU-WRF (Goddard radiation: six hours), and the default physics passed on five real cases. These comparisons also found and fixed many errors in how WRF schemes were called. An NVIDIA Ampere or newer GPU is required. The large microphysics lookup tables are attached to the GitHub release. Release notes · Validation report · Support matrix · Upgrade notes.

v0.3.4 — 10 October 2026

Fix release. gpuwrf run now uses or refuses every namelist physics option; v0.3.3 and earlier silently ran the default schemes when a different one was requested, so re-run such forecasts. Several schemes became available as experimental options. The default compiled program is unchanged; the first run recompiles once because the cache is tied to the version. Release notes · Support matrix.

v0.3.3 — 9 October 2026

Faster native Noah-MP radiation, corrected GPU memory layouts, Thompson snow fall speeds and stability safeguards for small grids. Seven 72-hour forecasts and the 24-hour Swiss case were compared with the original CPU-WRF; fields that went over their limits late in long runs are shown on the validation page. Release notes · 72-hour comparison plots.

Earlier releases

v0.3.2 — layout and startup (2026-10-05)

Stable nested layout pin, accepted momentum fusion, lazy dormant-scheme initialization and path-independent auxiliary caches. Matched 24-hour wall time falls 9.9% (3.669 to 3.305 s/hour under contention). N=4 × 24 h aggregate is 5.507 s/case-hour, 22.4× the CPU-WRF 3×4-core rate, including init/load and without compression. The two-domain Canary case is bit-identical to v0.3.1; the inner Tenerife domains differ at rounding level and pass the limits (innermost surface pressure 8.66 Pa versus 4.49 Pa, limit 120 Pa). Measurements and independent release verdict.

v0.3.1 — WRF-order fixes and performance (2026-10-05)

Open-top and per-record boundary-mass fixes, WRF edge-wind order, Andreas snow surface exchange, nested initial-state blending, thin-snow/ground-precipitation and warm-ice corrections, water/glacier history parity. the blocked acoustic vertical-velocity solver and Noah-MP column kernels are defaults; warm admission and three-nest memory planning are repaired.

Measured Canary 24-hour rate: 3.604 s/forecast hour (RTX 5090, AMD Ryzen 9 9950X), versus v0.3.0 4.126. Original CPU-WRF twelve-core reference: 92.3 s/hour. The Swiss January comparison and strict output checks pass all 25 frames in each domain. Evidence, clocks and limits.

A release-by-release summary. stability > identity is the top priority, but a proven correctness repair may intentionally change results and require a rebaseline, as v0.23.4 and v0.3.0 do. Full per-release notes live in the release_notes/ folder of the repository.

Reading the "default numerics" column

Byte-identical = same compiled program, bit-for-bit output vs the prior release. Numerically equivalent = value-preserving change to the program (proven CPU bit-identical + within the GPU autotune floor). New capability is almost always opt-in and inert by default.
