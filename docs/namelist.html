Namelist compatibility

wrf_gpu reads your WRF namelist.input as it is. Every option it understands is used exactly as requested; an option it cannot honour stops the run with a message that names it. Nothing is silently replaced by a default.

How your namelist is checked¶

gpuwrf run checks the namelist before any GPU work. A refused selection, a missing pairing or a missing input gives a short message naming the setting to change. You can run the same checks in advance:

gpuwrf doctor /path/to/case          # inputs, options, time step (CFL) and GPU memory
gpuwrf run --input-dir /path/to/case --output-dir runs/check --dry-run
gpuwrf namelist-support               # every physics code the program knows

Being accepted is not the same as being validated. This page and the physics options page give the status of each option in v0.4.1, using the same words: Default, Validated 24 h, Experimental, CPU only and Not supported (what they mean).

Analysis nudging (grid FDDA)¶

With grid_fdda=1, WRF's analysis nudging relaxes wind, temperature and water vapour towards gridded analyses during the forecast. wrf_gpu ports WRF's routine and reads the same input file. Validated 24 h in single-domain forecasts; nested domains are not validated.

Input. Run real.exe with the same &fdda settings; it writes wrffdda_d01 (named by gfdda_inname, NetCDF only). Put the file in the case directory next to wrfinput_d01 and wrfbdy_d01; each domain with grid_fdda=1 needs its own wrffdda_d0N. The file must hold one record per analysis time from the start to the end of nudging; a missing or short file, record times off the analysis interval, wrong grid sizes or invalid values stop the run before the forecast.

As written by real.exe, each record holds a pair of analyses: *_NDG_OLD at the record's time and *_NDG_NEW at the next analysis time. Between them the nudging target is interpolated linearly in time.

Fields (OLD and NEW)GridContent
U_NDG_OLD, U_NDG_NEWlevels × south_north × west_east_stagx-wind, m/s
V_NDG_OLD, V_NDG_NEWlevels × south_north_stag × west_easty-wind, m/s
T_NDG_OLD, T_NDG_NEWlevels × south_north × west_eastdry potential temperature minus 300 K, K
Q_NDG_OLD, Q_NDG_NEWlevels × south_north × west_eastwater vapour mixing ratio, kg/kg
PH_NDG_OLD, PH_NDG_NEWstaggered levels × south_north × west_eastgeopotential perturbation; needed only for spectral nudging (grid_fdda=2)

The nudging coefficients guv, gt and gq are in s-1.

&fdda
 grid_fdda            = 1,
 gfdda_inname         = "wrffdda_d<domain>",
 gfdda_interval_m     = 360,      ! analysis interval, minutes
 gfdda_end_h          = 24,       ! stop nudging after this many hours
 io_form_gfdda        = 2,
 fgdt                 = 0,        ! minutes between nudging updates (0 = every step)
 if_no_pbl_nudging_uv = 0, if_no_pbl_nudging_t = 1, if_no_pbl_nudging_q = 1,
 if_zfac_uv = 0, k_zfac_uv = 10, if_zfac_t = 0, k_zfac_t = 10, if_zfac_q = 0, k_zfac_q = 10,
 guv = 0.0003, gt = 0.0003, gq = 0.0003,
 if_ramping           = 0,
 dtramp_min           = 60.0,
/

Timing. As in WRF, analyses are read every gfdda_interval_m minutes from the start time and the nudging terms are updated every fgdt minutes (0 means every time step). When nudging ends depends on the ramp:

  • if_ramping=0: full strength until gfdda_end_h, then off.
  • if_ramping=1 with a positive dtramp_min: the ramp starts at gfdda_end_h and extends nudging beyond it, falling linearly to zero over dtramp_min minutes while the target is held at the most recent analysis. With gfdda_end_h=24 and dtramp_min=60, nudging is at half strength at 24.5 h and ends at 25 h.
  • if_ramping=1 with a negative dtramp_min: the ramp ends at gfdda_end_h. With gfdda_end_h=24 and dtramp_min=-60, nudging falls from full strength at 23 h to zero at 24 h.

What is nudged. The horizontal wind, potential temperature and water vapour; surface pressure and the air mass are not nudged. The nudging heat flux HFX_FDDA is written to the history files.

Restrictions. As in WRF, nudging starts at the model start (gfdda_begin_* must be 0) and times are given in gfdda_end_h and gfdda_interval_m. Switching off nudging inside the boundary layer (if_no_pbl_nudging_*=1) needs the MYNN boundary layer (bl_pbl_physics=5). Grid nudging cannot be combined with digital filter initialization or two-way nesting, Pleim-Xiu soil nudging (pxlsm_soil_nudge) is not supported, and an &fdda key the program does not know stops the run instead of being ignored. The history files lack WRF's global attributes FGDT, GUV, GT, GQ, IF_RAMPING and DTRAMP_MIN; the forecast itself is unaffected.

Restart. The nudging state is part of the checkpoints, so a resumed run continues nudging where it stopped. Checkpoints from versions without this state are refused.

Spectral nudging (grid_fdda=2) reads the same file (spectral nudging guide); surface nudging (grid_sfdda) adds a surface analysis file (surface nudging guide); observation nudging can run alongside (observation nudging guide).

New options in v0.4.1¶

Three &physics settings are new in v0.4.1. Leaving them out keeps the v0.4.0 behaviour. Each passed a 24-hour comparison with the original CPU-WRF in the set-ups named below, which is why they are marked Experimental: other combinations and regions have not been compared.

&physics
 topo_wind = 1, 1, 1,   ! per domain; acts only with bl_pbl_physics = 1 (YSU) or 11 (Shin-Hong)
 aer_opt   = 1,         ! one value; needs ra_sw_physics = 4 on every domain
 icloud    = 3,         ! one value; needs ra_lw_physics = 4 and ra_sw_physics = 4
/

Terrain correction of surface winds: topo_wind¶

WRF computes two fixed correction fields at start-up and the YSU and Shin-Hong boundary layers use them: extra surface drag over rough sub-grid terrain and, with option 1, a correction of the 10 m wind in valleys. wrf_gpu computes the same fields bit for bit. As in WRF, the option changes nothing with MYNN or any other boundary layer; the run prints a warning.

ValueMethodInputChecked against CPU-WRF
0off (default)——
1Jiménez and Dudhia (2012)VAR_SSO in wrfinput (WPS geogrid with the varsso data); refused without it, as in WRF24 h: Swiss Alps 3 km with YSU and with Shin-Hong; Tenerife 3 and 1 km nests with YSU
2Mass and Ovensgeogrid VAR24 h: Tenerife 9 km outer domain with YSU

Two-way feedback (feedback=1) passes the nest's correction fields to the parent as WRF does; this path is tested on the CPU only. 1 With YSU the compiled surface-layer kernel exceeds our per-thread memory limit; results are correct, the speed cost is not measured.

ValueMeaningChecked against CPU-WRF

Options 2 and 3 replace the whole default treatment in WRF's order, and history CLDFRA is the cloud fraction radiation saw. Both need RRTMG longwave and shortwave; icloud=3 refuses mp_physics=0/1/3. icloud=0 turns clouds off for radiation only, as in WRF: pair it with a normal run of the same case, from the same compile cache, to separate the radiative effect of clouds. Details in the cloud-fraction guide.

Digital filter initialization¶

Single-domain cases support dfi_opt=1/2/3 (DFL, DDFI and TDFI) with WRF's filter and window settings. DFL keeps its natural shifted timestamps, as in WRF. Nested DFI is not supported. With dfi_opt=0 or no setting nothing is filtered, and a resumed run does not filter again. The upgrade notes list the remaining restrictions.

Not supported in v0.4.2¶

  • Moving and vortex-following nests; adaptive time stepping.
  • WRF-Chem, WRF-Fire, WRF-Hydro, wave coupling and WRFDA variational data assimilation (the experimental LETKF of gpuwrf da is described on the tools page).
  • aer_opt=2.
  • km_opt=3 on the GPU; constant-K diffusion (km_opt=1) from the command line; surface mosaic (sf_surface_mosaic=1); the PWP ocean model (sf_ocean_physics=2); BEP+BEM tables that set GR_FRAC_ROOF without GR_FLAG=1; LCZ land use with BEP/BEM; two-way tracer feedback.
  • Two-way nesting with anything other than the default physics, with nudging, lakes, urban models or SST updates, or with an even parent_grid_ratio.
  • In nested runs: digital filter initialization, the RUC land model, the single-layer urban model and km_opt=2/5.
  • The physics codes marked Not supported on the physics page.

Options that have only single-domain evidence still run inside nests, but are not validated there. The support matrix lists the exact tested configurations and the evidence for each row.

Coming from v0.3¶

v0.3.3 and earlier could silently run the default schemes when a different scheme was requested. If you ran non-default physics with those versions, run the forecasts again. Checkpoints from earlier versions may not resume; see the upgrade notes.
