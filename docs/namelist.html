User's Guide › Configuration › Namelist Compatibility

Namelist compatibility

Use prepared WRF inputs and preserve the requested physics. The CLI binds admitted selections or refuses them with a named reason. The v0.4.0 candidate has frozen defaults and66 accepted registered scientific scopes (65 full24h plus c45 accepted6h); package review and publication approval remain separate.

Admission is separate from qualification¶

The per-option matrix distinguishes default, source-specific full24h bounded D6, experimental/E41/short/CPU-only and refused paths. A machine catalog entry or successful preflight is not an arbitrary-combination fidelity guarantee. See physics for selection scope.

GPU and input refusals¶

Smagorinsky km_opt=3 is GPU-refused. CAM-MG11 requires stock Triton3.6.x; its merged route retains native E41 FAIL and c89 scientific PASS/native E41 UNKNOWN. Historical GPU failures remain disclosed; CPU/reference paths are separate. sf_surface_mosaic=1 is refused. Crop, irrigation and groundwater branches need geographically valid maps. Unsupported pairings and keys set away from an unbound WRF default fail loudly.

Digital filter initialization¶

Single-domain native cases implement dfi_opt=1/2/3 (DFL/DDFI/TDFI) with documented filter, forcing, land and window restrictions. DFL keeps its natural shifted timestamps. Nested DFI is refused. Zero/omission skips filtering; a resumed run does not filter again. See the upgrade guide.

Optional model controls¶

Analysis/observation/spectral/surface nudging, stochastic forcing, turbines, tracers, diagnostics, urban/lake/ocean options and two-way feedback have admitted opt-in paths. Supply required forcing/configuration and check exact restrictions. These are not blanket out-of-scope features, nor universally qualified ones.

Nested not validated¶

For options with only single-domain evidence, explicitly report nested not validated where admission allows nesting. Existing refused combinations still fail. A finite nest smoke does not establish matched original-CPU fidelity.

Version and upgrade¶

v0.3.3 and earlier could silently execute default schemes for non-default requests. Re-run affected forecasts using the intended admitted scheme. Keep the versioned v0.3.4 record unchanged; use v0.4 status and restart/schema guidance for this candidate.

Inspect the installed interface¶

python -m gpuwrf.cli namelist-support --help
python -m gpuwrf.cli run --help

Original CPU-WRF or pristine WRF supplies fidelity truth. Older GPU output is regression evidence; source-changing merges need their affected gates before tag.
